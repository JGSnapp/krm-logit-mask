# KRM Logit Mask MVP

Прототип проверяет гипотезу из `Гипотеза_графы_компетенций_и_маскирование_исправленная_v2.pdf`:

1. извлекает из КРМ ИТМО компетенции, индикаторы, якоря Б/С/П и ролевую матрицу;
2. ограничивает генерацию графом допустимых ключевых выражений;
3. завершает выбор, только когда пересечение выражений задаёт одну компетенцию;
4. ограничивает свидетельство одним непрерывным токенизированным фрагментом исходного текста;
5. отдельным forced-choice шагом проверяет, поддерживает ли цитата выбранную компетенцию;
6. выбирает уровень из `Б / С / П / UNKNOWN` по условному правдоподобию, без свободной генерации метки.

Это исследовательский MVP, а не готовый HR-скоринг. `UNKNOWN` означает недостаточность свидетельств, а не отсутствие навыка. Автоматические уровни нельзя использовать для кадровых решений без экспертной валидации.

## Быстрый старт

Из корня этого каталога:

```bash
uv sync --extra dev
uv run pytest

uv run krm-mask extract-krm \
  '../КРМ/итмо/КРМ-версия3.0 (2).xlsx' \
  --output data/itmo_krm_3.json
```

Для локального запуска на GPU:

```bash
uv sync --extra gpu
uv run krm-mask run \
  --catalog data/itmo_krm_3.json \
  --text 'Писал SQL-запросы с оконными функциями и оптимизировал планы выполнения.' \
  --model Qwen/Qwen2.5-1.5B-Instruct
```

Прогон синтетического набора с единоразовой загрузкой модели:

```bash
uv run krm-mask evaluate \
  --catalog data/itmo_krm_3.json \
  --dataset data/synthetic_profiles.jsonl \
  --output data/evaluation.json
```

## Интерактивная трассировка

```bash
uv sync --extra gpu --extra web --extra dev
uv run krm-mask serve \
  --catalog data/itmo_krm_3.json \
  --model Qwen/Qwen2.5-1.5B-Instruct
```

Откройте `http://127.0.0.1:8000`. Интерфейс показывает каждый выбранный токен и
анимирует его посимвольно. Решение маски меняется на границах токенов — это явно
отделено от визуальной посимвольной анимации.

Replay автоматически проходит полный маршрут: выбор компетенции → одна
обязательная цитата → решение Qwen `ЕСТЬ ЕЩЁ / ЗАКОНЧИТЬ` → при необходимости
следующие непересекающиеся цитаты → support gate → оценка уровня → следующая компетенция.
Лимит до пяти цитат остаётся только защитой от зацикливания.
Для каждого этапа и всего запроса показывается время. В интерфейс включены четыре
длинных синтетических профиля, написанных обычным профессиональным языком без
копирования формулировок КРМ.

`generate()` сохраняет вероятность каждого фактически выбранного токена после
применения logits mask. Replay подсвечивает токены ниже регулируемого порога
красным. Это условная вероятность токена среди разрешённых продолжений, а не
калиброванная вероятность правильности всей компетенции.

Уверенность выбранной компетенции и каждой цитаты в интерфейсе определяется как
минимальная вероятность её сгенерированных токенов (`min p`). Следующий промпт
содержит историю ранее обработанных компетенций и подтверждённых цитат. Если
токенный префикс совместим только с одной компетенцией, генерация завершается
раньше, без достраивания полного выражения моделью.

Опционально маска разрешает специальный токен `.` на каждом шаге. Его выбор
помечает текущую генерацию как `aborted_generation`, и результат не принимается.
Второй переключатель требует сгенерировать ещё минимум два символа совместимого
выражения после того, как класс стал однозначным. После всего цикла Qwen выполняет
отдельную forced-choice самопроверку `ДА / НЕТ`: соответствует ли итог исходному
резюме и приведённым свидетельствам.

Модель загружается в `float16` на CUDA автоматически. Для 1.5B-модели на RTX 3080 Ti квантование не требуется. Имя модели является параметром CLI.

## Что именно маскируется

### Переключатель DISC

На обеих страницах анализа есть кнопка `DISC: выключен / включён` и бюджет
попыток K (по умолчанию 4). API принимает `use_disc` и `disc_budget` (1–8).
При выключенном DISC сохраняется прежний greedy-режим. При включённом DISC
контроллер повторяет весь выбор компетенции, включая несколько сигналов,
из одинакового исходного состояния. Цитаты и forced-choice проверки работают
как прежде. После K неудачных попыток принятия создаётся новая группа из K
проходов для взвешенного выбора; отвергнутые пути не переиспользуются.

Однозначные токены подставляются без вызова модели. Когда признак определился
по префиксу, его остаток дополняется существующим механизмом, затем выбирается
следующий совместимый признак. Подставленные токены остаются в контексте
следующего вызова. Вес накапливается в log-space только на неоднозначных шагах
по вероятностям **до** маски. Технический EOS имеет вес 1. Это адаптация DISC
к процессу с автоматически пройденными однозначными рёбрами, а не гарантия
воспроизведения исходного распределения полных строк из статьи.

Replay показывает выбранный путь, число проходов, их признаки и веса,
принятие / резервный выбор, число неоднозначных и автоматически пройденных
шагов. Полные данные доступны в JSON в `selection_trace[-1].disc`.
Незавершённые проходы учитываются в общем лимите 2K; если все резервные
проходы невалидны, API возвращает 422 вместо ложной компетенции.

- `PhraseGraphMask`: на каждом шаге оставляет конечными только токены, продолжающие допустимое ключевое выражение. Выражения можно выбирать в любом порядке. После каждой строки множество компетенций пересекается; EOS разрешается при одном оставшемся классе.
- `SourceSpanMask`: первый токен может начинать любой фрагмент исходного текста, каждый следующий обязан продолжать хотя бы одно совпавшее вхождение. После минимальной длины разрешается EOS. Поэтому составить «цитату» из несмежных мест нельзя.
- Поддержка: варианты `ДА / НЕТ` сравниваются по средней log-probability; это open-set gate после копирования цитаты.
- Уровень: четыре варианта оцениваются по средней log-probability. Это forced choice, а не генерируемое объяснение.

## Ограничения первой версии

- Граф ключевых выражений строится из названий и поля «Рекомендуемые темы» КРМ. Его нужно очищать и валидировать экспертами.
- Ролевой фильтр берётся из матрицы КРМ, но уровень роли не переносится автоматически на каждый индикатор.
- Синтетическая разметка в `data/synthetic_profiles.jsonl` иллюстративна; для эксперимента нужна слепая экспертная разметка.
- Автоматическая оценка Б/С/П — гипотеза. Главные метрики: accuracy/F1 компетенций, доля валидных дословных цитат, agreement с экспертами по уровням и отдельная ошибка `UNKNOWN`.
